Bug Tracking System

A Year 1, Trimester 3 web programming group project completed in 2025 as a web-based bug tracking system with role-based access control, project management, and developer assignment workflows.

Group project note: the source code for this project is available on GitHub, where the implementation uses Rust, Actix-web, Tera templates, and SQLite to support a role-based bug tracking workflow.

This project was built for the Web Programming module as a group-based bug tracking system. Instead of a simple static site, the repository implements a working web application with authentication, session handling, persistent data storage, and role-aware workflows for administrators, developers, and QA testers.

The system supports project creation, bug reporting, bug assignment, bug updates, and bug deletion through a mix of API endpoints and HTML template pages. The overall design is centered on practical workflow rules, such as restricting who can assign bugs, who can create projects, and how users interact with open defects across different roles.

From the repository structure, the app was built with Rust using Actix-web for the server layer, Tera for HTML templating, and SQLite for persistence. The project also shows attention to security and workflow concerns through password hashing, session-based authentication, and role-based permissions.

What we built

  • Built a web-based bug tracking system rather than a static site, with support for projects, bug reports, assignments, and user sessions.
  • Created role-based workflows so admins, developers, and QA testers could interact with the system under different permissions.
  • Included both API-style endpoints and template-based pages for actions such as login, registration, bug assignment, and bug updates.

Technical structure

  • Used Actix-web to define the server, routes, session middleware, and request handlers.
  • Used SQLite with SQLx queries for storing users, projects, and bug reports persistently.
  • Used Tera templates for HTML pages such as login, registration, bug assignment, and update forms.

Workflow logic

  • Admins could create projects and assign bugs broadly across developers.
  • QA users could create bugs and assign them to developers while avoiding invalid assignment cases such as assigning to QA users or themselves.
  • Developers could create and update bugs while staying within the role rules defined by the system.
